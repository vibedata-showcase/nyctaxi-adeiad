feat(finance): project the daily zone revenue report from the zone-day build

The report no longer aggregates fct_trip itself. It selects the build's
billable measures, renamed to its published columns, and keeps only zone-days
with a billable trip. Same grain, same eleven columns, same numbers: a full
outer join against the pre-change report returns 20,770 rows with zero
unmatched either side and zero differences on every count, label and money
column at the cent. Ravi's acceptance figures are exact: 9,604,511 trips,
263,480,834.99 revenue, and 416,460 trips and 33,881,378.28 revenue for JFK
Airport.

The billable predicate and the reporting window are gone from this model, so
there is one place they are evaluated (ADR 0018). trip_count's description now
says billable through a docs block: the contract generator sources that key
from the Ossie all-trips metric, which LTS7 refuses, so a hand-written string
was rewritten to a sentence the SQL contradicts.

Contract 1.0.2 is a patch: one description added, no property, rule or key
changed.
