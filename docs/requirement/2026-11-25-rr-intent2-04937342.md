# Requirement: RR_Intent2

## Ask

Ravi Menon, who owns the finance reports, asked for the daily zone revenue report Finance reads every morning to be built from the operations figures in `agg` instead of a second build from the trip fact, so that one source produces both. No number in the finance report may change. Finance's usual check, for Q1 2024: the report must total 95,958 trips and 2,629,185.82 revenue, and 4,120 trips and 337,711.05 revenue for JFK Airport.

Consumers: Finance's daily zone revenue report, which reads `finance.mart_daily_zone_revenue`; and Operations' own daily zone figures, which read `agg.agg_trip_zone_daily`. Neither is declared as a dbt exposure in this repo.

## Requirements

- [ ] `R-01` The finance report is built from the operations figures and from no other trip-level relation — accept when `mart_daily_zone_revenue` compiles reading `agg.agg_trip_zone_daily`, and `get_lineage` one hop upstream of the model reaches no other relation than `agg_trip_zone_daily` and `dim_zone` — source: request
- [ ] `R-02` Every published number in the finance report is unchanged — accept when a `EXCEPT ALL` comparison in both directions over all eleven published columns between the rebuilt `finance.mart_daily_zone_revenue` and the Domain's current table returns zero rows, and the report's row count is 7,961 — source: request
- [ ] `R-03` Finance's acceptance figures hold for Q1 2024 — accept when the rebuilt report totals 95,958 trips and 2,629,185.82 revenue, and totals 4,120 trips and 337,711.05 revenue for the zone `JFK Airport` — source: request
- [ ] `R-04` Operations' published figures are unchanged — accept when each of the 14 existing columns of `agg.agg_trip_zone_daily` compares `EXCEPT ALL`-equal in both directions to the Domain's current table over the reporting window (7,997 rows, 97,184 trips, 2,597,120.92 revenue) — source: request (one source, no number changes), repository
- [ ] `R-05` The billable rule is computed once for this grain — accept when exactly one model in the project computes billable zone-day measures, and the finance model carries no billable filter of its own — source: request, [ADR 0003](../../docs/adr/0003-billable-trip-definition-and-where-it-applies.md) as amended by the answer on the route
- [ ] `R-06` Descriptions, contracts and the semantic model match the relations as built — accept when `_finance.yml`, `_agg.yml`, both ODCS contracts and the Ossie documents agree with the built columns and their populations (no column described as "billable or not" that carries only billable trips), and `odcs_check`, `ossie_lint` and the semantic structural gates pass — source: repository — `_finance.yml` describes `mart_daily_zone_revenue.trip_count` as "Trips, billable or not." while the model filters to billable trips (95,958 of 97,184 in the window)
- [ ] `R-07` The semantic layer and its tests still answer the same questions — accept when `dbt build --select agg_trip_zone_daily+` and `dbt test --select mart_daily_zone_revenue,agg_trip_zone_daily` pass, including `assert_semantic_content_holds` and `assert_semantic_levels_hold` — source: repository

## Business decisions

| Decision | Value | Source |
| --- | --- | --- |
| Grain of the rebuilt report | One row per pickup zone and trip date (`trip_date` × `pickup_location_id`), unchanged | existing model `finance.mart_daily_zone_revenue` |
| Reuse | Build on the published `agg.agg_trip_zone_daily`, which already carries this grain, rather than a second aggregation from the fact | playbook default (Reuse), repository |
| Edge periods | Not applicable: the loaded window is 2024-01-01 to 2024-03-31 and the reporting window is exactly Q1, so no period is cut short | repository (`fct_trip` min/max pickup date, `dbt_project.yml` vars) |
| Coverage of the new billable measures | Publish the billable trip count beside every billable revenue measure, so a reader sees what the measure covers | playbook default (Coverage) |
| Measure on a zone-day with no billable trip | NULL, with `billable_trip_count` = 0 beside it, rather than 0 | playbook default (Coverage) |
| Unmatched and null keys | Keep every row: the zone join is on the surrogate `pickup_zone_key`, one row per trip, and no in-window trip has a null zone key (0 of 97,184) | repository |
| How the report is built from agg | **OPEN** — recommendation: agg gains billable measures beside its existing unfiltered ones, and the finance mart only selects and renames. Asked and unanswered | question to user; see `## Open questions` |
| Population of the finance report | **OPEN** — recommendation: keep omitting zone-days whose only trips are non-billable (36 zone-days, 37 trips in Q1 2024), so the report stays 7,961 rows. Asked and unanswered | question to user; see `## Open questions` |
| Where the billable rule is applied | **OPEN** — recommendation: computed once in `agg.agg_trip_zone_daily`. This departs from ADR 0003's sentence "Gold marts that report revenue or flows apply it, inside the reporting window: `mart_daily_zone_revenue`, …", so the answer needs an ADR. Asked and unanswered | [ADR 0003](../../docs/adr/0003-billable-trip-definition-and-where-it-applies.md), question to user |

## Out of scope

- `finance.mart_monthly_service_summary` and `finance.mart_revenue_component_bridge`, which keep building from `fct_trip`.
- The existing columns of `agg.agg_trip_zone_daily` and every other `agg`, `core` and `ops` model.
- The reporting window (`report_start`/`report_end`) and the loaded data.
- Retiring either relation, or changing either relation's key or partitioning.
- The ingestion pipelines.

## Open questions

1. **How the report is built from agg.** `agg.agg_trip_zone_daily` carries no billable measures: for Q1 2024 it totals 97,184 trips and 2,597,120.92 revenue over all in-window trips, while the finance report totals 95,958 and 2,629,185.82 over billable trips only. Built from agg as it stands, the report's numbers would change, which the request forbids. Recommendation: add billable measures to agg beside its existing unfiltered ones, so Operations' figures stay as they are and the finance mart becomes a projection. Holds `R-01`, `R-05`, the design stage, and an ADR amending ADR 0003.
2. **Whether the report keeps omitting zone-days with no billable trip.** 36 zone-days in Q1 2024 carry 37 trips and none billable, so the report has no row for them while agg does. Recommendation: keep omitting them, so `R-02`'s row count of 7,961 holds. Holds `R-02`, `R-03`.
