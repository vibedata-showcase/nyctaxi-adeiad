# Plan: mich

**Goal:** A gold relation `agg.agg_borough_flow_monthly` giving, for each month of Q1 2024, the billable trips and revenue from each borough to each borough plus the share of each origin borough's trips that cross a borough line, bound into the contracts and the semantic layer.

**Requirement:** `docs/requirement/2026-11-25-mich-8cb8e891.md`

**Constraints:**
- dbt models live under `transformation/`; a new gold model is `agg_`-prefixed in `transformation/models/marts/agg/` and its folder schema is `agg` (`+schema` in `dbt_project.yml`, accepted at design).
- Contract first: the ODCS contract at `contracts/agg/agg_borough_flow_monthly.odcs.yaml` is authored `status: proposed` before the SQL, set `active` once built, and every `data_type`, test, `contract: {enforced: true}` and description on the model comes from `odcs.py generate`, never by hand.
- `access: protected` on a boundary model; explicit column list, no `select *`; cast every expression to its declared type (DuckDB does not coerce to a contract type).
- Billable rule and reporting window applied here in gold (ADR 0003); the window comes from the `report_start` / `report_end` vars through `in_report_window()`, never hard-coded dates.
- Rates are rebuilt through `safe_divide` from summed numerators and denominators (ADR 0016); no floor (ADR 0019); crossing is equality on `dim_zone.borough_name` including unresolved groups and EWR (ADR 0018, ADR 0012).
- One singular test file per assertion, named `assert_<what_must_hold>.sql`; generic `not_null` on keys and measures; unit tests in `transformation/models/marts/agg/_unit_tests.yml`; data and unit tests run as separate commands.
- Nothing published today changes: `agg_od_flow_matrix`, the `finance` marts and the reporting window stay as they are (`R-09`).
