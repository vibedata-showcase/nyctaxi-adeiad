## Discovery

Recorded by `designing` before any artifact was written. Every query ran read-only against the Domain warehouse (`lakehouse_query`, target `domain`).

### The two relations disagree, and why

- Q1 2024 totals, both relations, in one statement:

  ```sql
  select 'finance_mart' as src, count(*) as row_count, sum(trip_count) as trips, sum(total_revenue) as revenue from finance.mart_daily_zone_revenue where trip_date >= DATE '2024-01-01' and trip_date < DATE '2024-04-01' union all select 'finance_mart_jfk', count(*), sum(trip_count), sum(total_revenue) from finance.mart_daily_zone_revenue where trip_date >= DATE '2024-01-01' and trip_date < DATE '2024-04-01' and zone_name = 'JFK Airport' union all select 'agg_trip_zone_daily', count(*), sum(trip_count), sum(total_revenue) from agg.agg_trip_zone_daily where pickup_date >= DATE '2024-01-01' and pickup_date < DATE '2024-04-01' union all select 'agg_trip_zone_daily_jfk', count(*), sum(trip_count), sum(total_revenue) from agg.agg_trip_zone_daily where pickup_date >= DATE '2024-01-01' and pickup_date < DATE '2024-04-01' and zone_name = 'JFK Airport'
  ```

  Result: finance mart 7,961 rows / 95,958 trips / 2,629,185.82; finance mart JFK 91 rows / 4,120 / 337,711.05; agg 7,997 rows / 97,184 / 2,597,120.92; agg JFK 91 rows / 4,261 / 329,766.06. The finance figures are exactly Finance's acceptance figures (R-03), so the Domain table is the baseline the rebuild must reproduce.

- The gap is the billable rule, not a join defect: `select is_billable, count(*) as trips, sum(total_amount) as revenue from core.fct_trip where pickup_date >= DATE '2024-01-01' and pickup_date < DATE '2024-04-01' group by 1` returns 95,958 billable trips / 2,629,185.82 and 1,226 non-billable trips / -32,064.90. `agg_trip_zone_daily` sums every in-window trip; `mart_daily_zone_revenue` filters `f.is_billable` (ADR 0003).

- At zone-day grain the two differ in population and in values:

  ```sql
  with f as (select trip_date, pickup_location_id, zone_name, trip_count, total_revenue from finance.mart_daily_zone_revenue where trip_date >= DATE '2024-01-01' and trip_date < DATE '2024-04-01'), a as (select pickup_date, pickup_location_id, zone_name, trip_count, total_revenue from agg.agg_trip_zone_daily where pickup_date >= DATE '2024-01-01' and pickup_date < DATE '2024-04-01') select 'only_in_finance' as side, count(*) as zone_days, sum(trip_count) as trips from f where not exists (select 1 from a where a.pickup_date=f.trip_date and a.pickup_location_id=f.pickup_location_id) union all select 'only_in_agg', count(*), sum(trip_count) from a where not exists (select 1 from f where a.pickup_date=f.trip_date and a.pickup_location_id=f.pickup_location_id) union all select 'both_value_differs', count(*), sum(f.trip_count-a.trip_count) from f join a on a.pickup_date=f.trip_date and a.pickup_location_id=f.pickup_location_id where f.trip_count <> a.trip_count or abs(f.total_revenue-a.total_revenue) > 0.005 union all select 'both_same', count(*), sum(f.trip_count) from f join a on a.pickup_date=f.trip_date and a.pickup_location_id=f.pickup_location_id where f.trip_count = a.trip_count and abs(f.total_revenue-a.total_revenue) <= 0.005
  ```

  Result: only_in_finance 0 zone-days; only_in_agg 36 zone-days / 37 trips; both_value_differs 962 zone-days; both_same 6,999 zone-days. So every finance row has an agg counterpart, and agg carries 36 zone-days finance does not.

- The 36 extra zone-days carry no billable trip at all:

  ```sql
  with agg as (select a.pickup_date, a.pickup_location_id, a.trip_count from agg.agg_trip_zone_daily a where a.pickup_date >= DATE '2024-01-01' and a.pickup_date < DATE '2024-04-01'), nb as (select pickup_date, pickup_location_id, count(*) filter (where not is_billable) as non_billable_trips from core.fct_trip f join core.dim_zone z on f.pickup_zone_key=z.zone_key where pickup_datetime >= timestamp '2024-01-01' and pickup_datetime < timestamp '2024-04-01' group by 1,2) select count(*) as zone_days_zero_billable, sum(a.trip_count) as trips_in_them, sum(nb.non_billable_trips) as non_billable_trips from agg a join nb using (pickup_date, pickup_location_id) where not exists (select 1 from core.fct_trip f join core.dim_zone z on f.pickup_zone_key=z.zone_key where f.pickup_date=a.pickup_date and z.zone_natural_key=a.pickup_location_id and f.is_billable)
  ```

  Result: 36 zone-days, 37 trips, 37 non-billable trips. They drop out of a billable-only aggregation; they do not drop out of `agg_trip_zone_daily`.

### Input adequacy: the billable measures reproduce the report exactly

- Recomputing the mart's eleven columns from `fct_trip` and comparing column-for-column gave an exact match, so a rebuild is feasible:

  ```sql
  -- candidate: billable measures at zone x date from fct_trip + dim_zone, joined to dim_zone for
  -- reporting_region on the natural key with the half-open validity interval
  with cand as (
    select a.pickup_date as trip_date, a.pickup_location_id, dz.borough_name as borough, a.zone_name, dz.reporting_region,
           a.billable_trip_count as trip_count, a.fare_revenue, a.tip_revenue, a.surcharge_revenue, a.toll_revenue,
           a.billable_revenue as total_revenue
    from (select f.pickup_date, z2.zone_natural_key as pickup_location_id, z2.zone_name,
                 count(*) filter (where f.is_billable) as billable_trip_count,
                 sum(f.total_amount) filter (where f.is_billable) as billable_revenue,
                 sum(f.fare_amount) filter (where f.is_billable) as fare_revenue,
                 sum(f.tip_amount) filter (where f.is_billable) as tip_revenue,
                 sum(f.total_surcharges) filter (where f.is_billable) as surcharge_revenue,
                 sum(f.tolls_amount) filter (where f.is_billable) as toll_revenue
          from core.fct_trip f join core.dim_zone z2 on f.pickup_zone_key = z2.zone_key
          where f.pickup_datetime >= timestamp '2024-01-01' and f.pickup_datetime < timestamp '2024-04-01'
          group by 1,2,3) a
    left join core.dim_zone dz on dz.zone_natural_key = a.pickup_location_id
        and a.pickup_date >= dz.valid_from_date and a.pickup_date < dz.valid_to_date
  ), mart as (
    select trip_date, pickup_location_id, borough, zone_name, reporting_region, trip_count,
           fare_revenue, tip_revenue, surcharge_revenue, toll_revenue, total_revenue
    from finance.mart_daily_zone_revenue
  )
  select 'cand_not_in_mart' as side, count(*) as n from (select * from cand except all select * from mart) x
  union all select 'mart_not_in_cand', count(*) from (select * from mart except all select * from cand) y
  union all select 'cand_rows', count(*) from cand
  union all select 'null_region_in_cand', count(*) from cand where reporting_region is null
  ```

  Result: cand_not_in_mart 36 (the zero-billable zone-days, which the mart omits today); mart_not_in_cand 0; cand_rows 7,997; null_region_in_cand 0. Filtering the 36 out made the comparison exact in both directions (0 and 0), and the four acceptance figures came out at 95,958 / 2,629,185.82 and 4,120 / 337,711.05. This is the evidence behind the two questions asked at the requirement stop.

### The chosen variant, measured

- Route: billable measures carried at the agg grain. Population: the 36 zero-billable zone-days published with zero measures. Measured on the same candidate with `coalesce(..., 0)` and no `billable_trip_count > 0` filter:

  ```sql
  -- same candidate CTE as above, with coalesce(a.<measure>, 0) and no billable>0 filter
  select 'cand_rows' k, count(*)::double v from cand
  union all select 'null_region', count(*)::double from cand where reporting_region is null
  union all select 'grain_dupes', count(*)::double from (select trip_date, pickup_location_id from cand group by 1,2 having count(*)>1) x
  union all select 'q1_trips', sum(trip_count) from cand
  union all select 'q1_rev', sum(total_revenue) from cand
  union all select 'jfk_trips', sum(trip_count) from cand where zone_name='JFK Airport'
  union all select 'jfk_rev', sum(total_revenue) from cand where zone_name='JFK Airport'
  union all select 'existing_rows_preserved', count(*) from mart m where exists (select 1 from cand c where c.trip_date=m.trip_date and c.pickup_location_id=m.pickup_location_id and c.trip_count=m.trip_count and c.total_revenue=m.total_revenue and c.fare_revenue=m.fare_revenue and c.tip_revenue=m.tip_revenue and c.surcharge_revenue=m.surcharge_revenue and c.toll_revenue=m.toll_revenue)
  union all select 'new_zero_rows', count(*) from cand c where c.trip_count=0
  ```

  Result: 7,997 rows; 0 null `reporting_region`; 0 grain duplicates; Q1 95,958 trips / 2,629,185.82; JFK 4,120 / 337,711.05; 7,961 existing rows preserved with every measure equal; 36 new all-zero rows.

- The semantic content test for the finance mart still holds with the 36 zero rows present:

  ```sql
  with cand as (select a.pickup_date as trip_date, a.pickup_location_id, a.billable_trip_count as trip_count, coalesce(a.billable_revenue,0) as total_revenue from (select f.pickup_date, z2.zone_natural_key as pickup_location_id, count(*) filter (where f.is_billable) as billable_trip_count, sum(f.total_amount) filter (where f.is_billable) as billable_revenue from core.fct_trip f join core.dim_zone z2 on f.pickup_zone_key = z2.zone_key where f.pickup_datetime >= timestamp '2024-01-01' and f.pickup_datetime < timestamp '2024-04-01' group by 1,2) a),
  detail as (select d0.calendar_date as day, d1.zone_natural_key as zone, sum(case when f.is_billable then 1 else 0 end) as billable_trip_count, sum(case when f.is_billable then f.total_amount else 0 end) as billable_revenue from core.fct_trip f left join core.dim_date d0 on f.pickup_date_key = d0.date_key left join core.dim_zone d1 on f.pickup_zone_key = d1.zone_key where f.pickup_date >= DATE '2024-01-01' and f.pickup_date < DATE '2024-04-01' and f.is_billable and f.pickup_zone_key is not null group by 1,2)
  select count(*) as s5_findings_after_change from cand s full join detail d on s.trip_date is not distinct from d.day and s.pickup_location_id is not distinct from d.zone where coalesce(s.trip_count,0) is distinct from coalesce(d.billable_trip_count,0) or ((coalesce(s.total_revenue,0) is null) <> (coalesce(d.billable_revenue,0) is null) or abs(coalesce(s.total_revenue,0) - coalesce(d.billable_revenue,0)) > 0.01)
  ```

  Result: 0 findings. The test's full join with `coalesce(..., 0)` already tolerates a zone-day present on one side only.

### Join and grain facts the design depends on

- `dim_zone` is Type 2 (ADR 0009): `select (select count(*) from core.dim_zone) as dim_zone_rows, (select count(*) from core.dim_zone where is_current_version) as current_rows, (select count(*) from (select zone_natural_key from core.dim_zone group by 1 having count(*)>1)) as zones_with_versions, (select count(*) from (select trip_date, pickup_location_id, count(*) c from finance.mart_daily_zone_revenue group by 1,2 having c>1)) as dup_fin, (select count(*) from (select pickup_date, pickup_location_id, count(*) c from agg.agg_trip_zone_daily group by 1,2 having c>1)) as dup_agg` returned 272 rows, 265 current, 7 zones with more than one version, 0 duplicate grains in either mart.

- Joining `dim_zone` on the natural key alone fans out: `select (select count(*) from m) as mart_rows, (select count(*) from m join core.dim_zone z on z.zone_natural_key = m.pickup_location_id) as joined_all_versions, (select count(*) from m join core.dim_zone z on z.zone_natural_key = m.pickup_location_id and z.is_current_version) as joined_current from (select trip_date, pickup_location_id from finance.mart_daily_zone_revenue) m` gave 7,961 rows joining to 8,184 rows on all versions and 7,961 on current-only. The rebuild must carry the interval, not the bare key.

- Zone attributes agree between the mart and the current dimension version: grouping the mart against `core.dim_zone` filtered `is_current_version` on `zone_name`, `borough_name` and `reporting_region` returned 0 rows of difference, so a `reporting_region` lookup adds no divergence.

- The window is exactly Q1 and not cut short: `select min(pickup_date) as min_d, max(pickup_date) as max_d, count(*) as trips, count(*) filter (where pickup_zone_key is null) as null_zone_key from core.fct_trip` returned 2024-01-01, 2024-03-31, 97,184 trips and 0 null zone keys; `select count(distinct pickup_date) as days ...` returned 91 distinct dates.

- No billable trip has a null fare component, so the five billable sums never need a null policy of their own: `select count(*) as billable_trips, count(*) filter (where fare_amount is null) as null_fare, count(*) filter (where tip_amount is null) as null_tip, count(*) filter (where tolls_amount is null) as null_toll, count(*) filter (where total_surcharges is null) as null_surch, count(*) filter (where total_amount is null) as null_total from core.fct_trip where is_billable and pickup_datetime >= timestamp '2024-01-01' and pickup_datetime < timestamp '2024-04-01'` returned 95,958 and 0 for every null count.

### Descriptions that disagree with the data

- `_finance.yml` describes `mart_daily_zone_revenue.trip_count` as "Trips, billable or not.", but every row of the built relation is billable-filtered: 95,958 of 97,184 in-window trips. Recorded as R-06.

- `logical-model/nyc_taxi_analytics.ossie.yaml` LTS7's `note` refuses `trip_count` with "the mart applies `f.is_billable`, so its trip_count is the billable count", which is true today and stays true after the rebuild, but its reason changes from a filter the mart applies to a measure it inherits.
