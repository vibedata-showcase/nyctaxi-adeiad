- JFK Airport, Q1 2024: finance 4,120 trips / 337,711.05 revenue; agg 4,261 / 329,766.06. The report's own check figures are confirmed against the shipped relation. — `select 'finance_jfk' as k, sum(trip_count) trips, sum(total_revenue) rev from finance.mart_daily_zone_revenue where trip_date>=DATE '2024-01-01' and trip_date<DATE '2024-04-01' and zone_name = 'JFK Airport' union all select 'agg_jfk', sum(trip_count), sum(total_revenue) from agg.agg_trip_zone_daily where pickup_date>=DATE '2024-01-01' and pickup_date<DATE '2024-04-01' and zone_name = 'JFK Airport' union all select 'agg_jfk_filtered_join', sum(a.trip_count), sum(a.total_revenue) from agg.agg_trip_zone_daily a join finance.mart_daily_zone_revenue f on a.pickup_date=f.trip_date and a.pickup_location_id=f.pickup_location_id and f.zone_name='JFK Airport' where a.zone_name='JFK Airport'`
- Restricting the aggregation to billable trips reproduces the report exactly, so the rebuild is provable: 7,961 rows, 95,958 trips, 2,629,185.82 revenue, and 36 zone-days that fall away. — `select count(*) as zone_days_all, count(*) filter (where billable_n > 0) as zone_days_with_billable, sum(n) trips_all, sum(billable_n) trips_billable, round(sum(rev_all),2) rev_all, round(sum(rev_billable),2) rev_billable, round(sum(rev_all)-sum(rev_billable),2) as excluded_rev from (select f.pickup_date, z.zone_natural_key as zid, count(*) n, count(*) filter (where f.is_billable) billable_n, sum(f.total_amount) rev_all, sum(f.total_amount) filter (where f.is_billable) rev_billable from core.fct_trip f join core.dim_zone z on f.pickup_zone_key = z.zone_key where f.pickup_datetime >= TIMESTAMP '2024-01-01' and f.pickup_datetime < TIMESTAMP '2024-04-01' group by 1,2)`
- Row-level equivalence of the rebuilt population against the shipped report: 7,961 rows both sides, 0 unmatched on either side, 0 differences on trip_count and on all four components and the total. — `with bill as (select f.pickup_date as trip_date, z.zone_natural_key as pickup_location_id, count(*) filter (where f.is_billable) as trip_count, sum(f.fare_amount) filter (where f.is_billable) as fare_revenue, sum(f.tip_amount) filter (where f.is_billable) as tip_revenue, sum(f.total_surcharges) filter (where f.is_billable) as surcharge_revenue, sum(f.tolls_amount) filter (where f.is_billable) as toll_revenue, sum(f.total_amount) filter (where f.is_billable) as total_revenue from core.fct_trip f join core.dim_zone z on f.pickup_zone_key = z.zone_key where f.pickup_datetime >= TIMESTAMP '2024-01-01' and f.pickup_datetime < TIMESTAMP '2024-04-01' group by 1,2) select count(*) as finance_rows, count(b.trip_date) as matched, sum(case when f.trip_date is null then 1 else 0 end) as only_in_bill, sum(case when b.trip_date is null then 1 else 0 end) as only_in_finance, sum(case when b.trip_count <> f.trip_count then 1 else 0 end) as trip_count_diffs, sum(case when abs(b.fare_revenue - f.fare_revenue) > 1e-9 then 1 else 0 end) as fare_diffs, sum(case when abs(b.tip_revenue - f.tip_revenue) > 1e-9 then 1 else 0 end) as tip_diffs, sum(case when abs(b.surcharge_revenue - f.surcharge_revenue) > 1e-9 then 1 else 0 end) as surcharge_diffs, sum(case when abs(b.toll_revenue - f.toll_revenue) > 1e-9 then 1 else 0 end) as toll_diffs, sum(case when abs(b.total_revenue - f.total_revenue) > 1e-9 then 1 else 0 end) as total_diffs from finance.mart_daily_zone_revenue f full outer join bill b on f.trip_date = b.trip_date and f.pickup_location_id = b.pickup_location_id`
- The Q1 profile the rebuilt relation must keep: 7,961 rows, 95,958 trips, fare 1,802,576.08, tip 313,865.43, surcharge 481,752.42, toll 51,368.39, total 2,629,185.82, 261 zones, 2024-01-01 to 2024-03-31, no null borough or reporting region, no null or non-positive trip count. — `select count(*) rows_, sum(trip_count) trips, round(sum(fare_revenue),2) fare, round(sum(tip_revenue),2) tip, round(sum(surcharge_revenue),2) surcharge, round(sum(toll_revenue),2) toll, round(sum(total_revenue),2) total, count(distinct pickup_location_id) zones, min(trip_date) min_d, max(trip_date) max_d, count(*) filter (where borough is null) null_borough, count(*) filter (where reporting_region is null) null_region from finance.mart_daily_zone_revenue where trip_date >= DATE '2024-01-01' and trip_date < DATE '2024-04-01'`
- The report's `reporting_region` takes four values over Q1 (Manhattan Core 5,092 rows, Outer Boroughs 2,730, Unresolved 127, Out of State 12). The aggregate does not carry the column, so the rebuild must add it there rather than re-join the zone dimension. — `select f.reporting_region, count(*) as n from finance.mart_daily_zone_revenue f group by 1 order by 2 desc limit 10`
- Re-joining the zone dimension to the aggregate fans out: 7 zone natural keys carry two SCD2 versions, and a natural-key join returns two rows for those zone-days (e.g. 2024-02-12, zones 148 and 74). A rebuild that re-joined `dim_zone` would duplicate rows and double revenue. — `select count(*) as natural_keys_with_multi_rows, max(n) as max_versions from (select zone_natural_key, count(*) as n from core.dim_zone group by 1 having count(*) > 1) t`; `select a.pickup_date, a.pickup_location_id, count(*) as join_rows from agg.agg_trip_zone_daily a join core.dim_zone z on a.pickup_location_id = z.zone_natural_key group by 1,2 having count(*) > 1 limit 5`
- All versions of a zone agree on the attributes the report publishes, so reading them from the aggregate cannot relabel a row: 0 differences on zone name, borough and reporting region across all 7,961 matched zone-days. — `select sum(case when a.zone_name is distinct from f.zone_name then 1 else 0 end) as zone_name_diff, sum(case when a.borough_name is distinct from f.borough then 1 else 0 end) as borough_diff, count(*) as matched from finance.mart_daily_zone_revenue f join agg.agg_trip_zone_daily a on f.trip_date = a.pickup_date and f.pickup_location_id = a.pickup_location_id`; `select sum(case when z.reporting_region is distinct from f.reporting_region then 1 else 0 end) as region_diff, count(*) as matched from finance.mart_daily_zone_revenue f join core.dim_zone z on z.zone_natural_key = f.pickup_location_id`
- No trip in the window lacks a resolvable pickup zone, and the aggregate has no null zone key or zone name, so no join in the rebuild can drop or merge a row. — `select count(*) as trips_null_zone from core.fct_trip where pickup_zone_key is null or pickup_zone_key not in (select zone_key from core.dim_zone)`; `select count(*) as all_agg_rows, count(*) filter (where pickup_location_id is null) as null_loc, count(*) filter (where zone_name is null) as null_zone, count(*) filter (where borough_name is null) as null_borough from agg.agg_trip_zone_daily`
- No trip in the window has a null fare, tip, toll, surcharge total or total amount, so a plain `sum()` and a coalesced sum are the same number and the NULL question does not arise. — `select count(*) as trips, count(*) filter (where fare_amount is null) as null_fare, count(*) filter (where tip_amount is null) as null_tip, count(*) filter (where tolls_amount is null) as null_toll, count(*) filter (where total_amount is null) as null_total, count(*) filter (where total_surcharges is null) as null_sur, count(*) filter (where is_billable) as billable from core.fct_trip where pickup_datetime >= TIMESTAMP '2024-01-01' and pickup_datetime < TIMESTAMP '2024-04-01'`
- The report's edge periods are not cut short: the window is 91 days and 91 are present, spanning 2024-01-01 00:05:25 to 2024-03-31 23:56:17 of pickup timestamps with no partial day at either end. — `select min(pickup_date) as min_d, max(pickup_date) as max_d, count(distinct pickup_date) as days, min(pickup_datetime) as min_ts, max(pickup_datetime) as max_ts from core.fct_trip`; `select count(distinct trip_date) as days_present, datediff('day', DATE '2024-01-01', DATE '2024-04-01') as days_in_window from finance.mart_daily_zone_revenue where trip_date >= DATE '2024-01-01' and trip_date < DATE '2024-04-01'`
- Neither relation has a duplicate at its grain, so the grain is unchanged by the rebuild and uniqueness can be asserted on the output. — `select 'finance_dupes' k, count(*) n from (select trip_date, pickup_location_id from finance.mart_daily_zone_revenue group by 1,2 having count(*)>1) union all select 'agg_dupes', count(*) from (select pickup_date, pickup_location_id from agg.agg_trip_zone_daily group by 1,2 having count(*)>1)`
