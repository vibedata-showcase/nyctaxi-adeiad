### D1. The two relations do not agree today

```sql
select count(*) as rows, sum(trip_count) as trips, round(sum(total_revenue),2) as revenue,
       sum(case when zone_name = 'JFK Airport' then trip_count end) as jfk_trips,
       round(sum(case when zone_name = 'JFK Airport' then total_revenue end),2) as jfk_revenue
from finance.mart_daily_zone_revenue
-- rows 7961, trips 95958, revenue 2629185.82, jfk_trips 4120, jfk_revenue 337711.05
```

```sql
select count(*) as rows, sum(trip_count) as trips, round(sum(total_revenue),2) as revenue,
       sum(case when zone_name = 'JFK Airport' then trip_count end) as jfk_trips,
       round(sum(case when zone_name = 'JFK Airport' then total_revenue end),2) as jfk_revenue
from agg.agg_trip_zone_daily
-- rows 7997, trips 97184, revenue 2597120.92, jfk_trips 4261, jfk_revenue 329766.06
```

The finance report reproduces Ravi Menon's acceptance figures exactly. The agg does not:
it counts every in-window trip, refunds included, and sums their totals.

### D2. The population gap is the billable rule, not an error

```sql
select count(*) as trips, round(sum(total_amount),2) as rev,
       count(*) filter (where is_billable) as billable_trips,
       round(sum(total_amount) filter (where is_billable),2) as billable_rev,
       count(*) filter (where pickup_zone_key is null) as null_zone
from core.fct_trip
where pickup_datetime >= DATE '2024-01-01' and pickup_datetime < DATE '2024-04-01'
-- trips 97184, rev 2597120.92, billable_trips 95958, billable_rev 2629185.82, null_zone 0
```

The agg's totals are `fct_trip` unfiltered; the report's are the billable subset
(ADR 0003). No in-window trip has a null pickup zone, so the report's inner join to
`dim_zone` drops no row.

### D3. A billable rollup at the agg's grain reproduces the report exactly

```sql
with base as (
  select f.pickup_date, z.zone_natural_key as pickup_location_id, z.borough_name,
         z.zone_name, z.reporting_region,
         count(*) filter (where f.is_billable) as billable_trip_count,
         sum(f.fare_amount) filter (where f.is_billable) as billable_fare_revenue,
         sum(f.tip_amount) filter (where f.is_billable) as billable_tip_revenue,
         sum(f.total_surcharges) filter (where f.is_billable) as billable_surcharge_revenue,
         sum(f.tolls_amount) filter (where f.is_billable) as billable_toll_revenue,
         sum(f.total_amount) filter (where f.is_billable) as billable_total_revenue
  from core.fct_trip f join core.dim_zone z on f.pickup_zone_key = z.zone_key
  where f.pickup_datetime >= DATE '2024-01-01' and f.pickup_datetime < DATE '2024-04-01'
  group by 1,2,3,4,5
), fin as (select * from finance.mart_daily_zone_revenue)
select (select count(*) from base) as base_rows,
       (select count(*) from base where billable_trip_count > 0) as base_billable_rows,
       (select count(*) from fin) as fin_rows,
       (select count(*) from base b join fin f on f.trip_date=b.pickup_date and f.pickup_location_id=b.pickup_location_id
          where b.billable_trip_count=f.trip_count and b.billable_fare_revenue=f.fare_revenue
            and b.billable_tip_revenue=f.tip_revenue and b.billable_surcharge_revenue=f.surcharge_revenue
            and b.billable_toll_revenue=f.toll_revenue and b.billable_total_revenue=f.total_revenue
            and b.borough_name=f.borough and b.zone_name=f.zone_name
            and b.reporting_region=f.reporting_region) as exact_matches,
       (select count(*) from base where billable_trip_count > 0
          and (billable_fare_revenue is null or billable_tip_revenue is null
               or billable_surcharge_revenue is null or billable_toll_revenue is null
               or billable_total_revenue is null)) as null_measure_rows
-- base_rows 7997, base_billable_rows 7961, fin_rows 7961,
-- exact_matches 7961, null_measure_rows 0
```

Every one of the report's 7,961 rows, on all eleven columns, matches a billable rollup
at the agg's grain. This is what makes "no number changes" reachable.

### D4. The 36 zone-days the report omits, and their totals

```sql
with a as (select pickup_date, pickup_location_id, trip_count, total_revenue from agg.agg_trip_zone_daily)
select count(*) as agg_only_rows, sum(trip_count) as trips_agg_only,
       round(sum(total_revenue),2) as rev_agg_only
from a where not exists (select 1 from finance.mart_daily_zone_revenue f
                         where f.trip_date=a.pickup_date and f.pickup_location_id=a.pickup_location_id)
-- agg_only_rows 36, trips_agg_only 37, rev_agg_only -545.1
```

```sql
select count(*) as zero_billable_rows, sum(trip_count) as trips_in_them,
       count(*) filter (where total_revenue = 0) as zero_rev,
       count(*) filter (where total_revenue < 0) as neg_rev
from agg.agg_trip_zone_daily a
where not exists (select 1 from finance.mart_daily_zone_revenue f
                  where f.trip_date=a.pickup_date and f.pickup_location_id=a.pickup_location_id)
-- zero_billable_rows 36, trips_in_them 37, zero_rev 2, neg_rev 34
```

Each omitted zone-day holds 1-2 trips, all refunds: no billable trip, no positive
revenue. Keeping them absent is the user's answer (R-08), and it keeps the report at
7,961 rows.

### D5. No report measure is null on a billable trip

```sql
select count(*) filter (where total_amount is null) as null_total,
       count(*) filter (where fare_amount is null) as null_fare,
       count(*) filter (where tip_amount is null) as null_tip,
       count(*) filter (where total_surcharges is null) as null_surch,
       count(*) filter (where tolls_amount is null) as null_tolls
from core.fct_trip
where pickup_datetime >= DATE '2024-01-01' and pickup_datetime < DATE '2024-04-01' and is_billable
-- null_total 0, null_fare 0, null_tip 0, null_surch 0, null_tolls 0
```

No `coalesce` belongs in the report's sums: a null and a zero would give the same
figures here, and introducing one would hide a future change in the source.

### D6. `reporting_region` and the zone labels are constant within a zone-day

`dim_zone` is Type-2: 272 rows over 265 natural keys, so a zone's version can change
inside the window.

```sql
with g as (
  select f.pickup_date, z.zone_natural_key, z.zone_name, z.borough_name, z.reporting_region, count(*) as n
  from core.fct_trip f join core.dim_zone z on f.pickup_zone_key = z.zone_key
  where f.pickup_datetime >= DATE '2024-01-01' and f.pickup_datetime < DATE '2024-04-01'
  group by 1,2,3,4,5
)
select count(*) as groups_with_region,
       (select count(*) from (select distinct pickup_date, zone_natural_key from g)) as groups_date_zone
from g
-- groups_with_region 7997, groups_date_zone 7997
```

```sql
with lab as (select distinct pickup_date, pickup_location_id, zone_name, borough_name from agg.agg_trip_zone_daily),
d as (select f.pickup_date, z.zone_natural_key as pickup_location_id, z.zone_name as d_zone,
             z.borough_name as d_boro, z.reporting_region
      from core.fct_trip f join core.dim_zone z on f.pickup_zone_key = z.zone_key
      where f.pickup_datetime >= DATE '2024-01-01' and f.pickup_datetime < DATE '2024-04-01'
      group by 1,2,3,4,5)
select count(*) as rows_compared,
       count(*) filter (where lab.zone_name is distinct from d.d_zone) as zone_name_diff,
       count(*) filter (where lab.borough_name is distinct from d.d_boro) as borough_diff
from lab join d on d.pickup_date = lab.pickup_date and d.pickup_location_id = lab.pickup_location_id
-- rows_compared 7997, zone_name_diff 0, borough_diff 0
```

Adding `reporting_region` to the agg does not split its grain, and the agg's existing
`zone_name`/`borough_name` already equal `dim_zone`'s at the report's grain, so the
report can read its zone labels from the agg without a second join.

### D9. Existing model descriptions disagree with the data

`_finance.yml` describes `mart_daily_zone_revenue.trip_count` as "Trips, billable or
not", and `_agg.yml` uses the same sentence for `agg_trip_zone_daily.trip_count`. For
the report that is wrong (it filters on `is_billable`: 95,958 of 97,184), and for the
agg it is right. The logical model's `LTS7_daily_zone_revenue` note already records
the correct reading. Corrected under R-10.
