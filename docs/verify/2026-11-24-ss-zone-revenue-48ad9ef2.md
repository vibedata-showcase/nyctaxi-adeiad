# Verification: SS · zone revenue

## Discovery

Written by `designing` before any artifact was authored. Every line is a query that ran this session against `domain`.

- `mart_daily_zone_revenue` is at the same grain as `agg_trip_zone_daily` and their populations already differ: finance 7,961 rows / 95,958 trips / 2,629,185.82, agg 7,997 rows / 97,184 trips / 2,597,120.92 for Q1 2024 — `select 'finance' as src, count(*) as rows, sum(trip_count) as trips, round(sum(total_revenue),2) as revenue from finance.mart_daily_zone_revenue where trip_date >= DATE '2024-01-01' and trip_date < DATE '2024-04-01' union all select 'agg', count(*), sum(trip_count), round(sum(total_revenue),2) from agg.agg_trip_zone_daily where pickup_date >= DATE '2024-01-01' and pickup_date < DATE '2024-04-01'`
- JFK Airport, Q1 2024: finance 4,120 trips / 337,711.05, agg 4,261 / 329,766.06 — `select 'finance' as src, z.zone_name, sum(f.trip_count) as trips, round(sum(f.total_revenue),2) as revenue from finance.mart_daily_zone_revenue f join core.dim_zone z on z.zone_natural_key = f.pickup_location_id where f.trip_date >= DATE '2024-01-01' and f.trip_date < DATE '2024-04-01' and z.zone_name ilike '%JFK%' group by 1,2 union all select 'agg', z.zone_name, sum(a.trip_count), round(sum(a.total_revenue),2) from agg.agg_trip_zone_daily a join core.dim_zone z on z.zone_natural_key = a.pickup_location_id where a.pickup_date >= DATE '2024-01-01' and a.pickup_date < DATE '2024-04-01' and z.zone_name ilike '%JFK%' group by 1,2`
- The gap is the billable rule: `fct_trip` holds 97,184 in-window trips, 95,958 of them billable, with no null pickup zone key — `select count(*) as in_window_trips, count(*) filter (where is_billable) as billable, count(*) filter (where pickup_zone_key is null) as null_zone, count(*) filter (where is_billable and pickup_zone_key is null) as billable_null_zone from core.fct_trip where pickup_datetime >= TIMESTAMP '2024-01-01' and pickup_datetime < TIMESTAMP '2024-04-01'`
- Billable zone-day sums reproduce `mart_daily_zone_revenue` exactly, so a build from the aggregate can be value-identical: 7,961 rows both sides, 0 rows only in the recomputation, 0 only in the mart — `with b as (select f.pickup_date as trip_date, z.zone_natural_key as pickup_location_id, z.borough_name as borough, z.zone_name, z.reporting_region, count(*) as trip_count, sum(f.fare_amount) as fare_revenue, sum(f.tip_amount) as tip_revenue, sum(f.total_surcharges) as surcharge_revenue, sum(f.tolls_amount) as toll_revenue, sum(f.total_amount) as total_revenue from core.fct_trip f join core.dim_zone z on f.pickup_zone_key = z.zone_key where f.pickup_datetime >= TIMESTAMP '2024-01-01' and f.pickup_datetime < TIMESTAMP '2024-04-01' and f.is_billable group by 1,2,3,4,5) select ... except ...`
- 36 zone-days in Q1 carry trips but no billable trip: 37 trips, -545.10 of all-trip revenue; all 36 are absent from the finance mart and none has a zero-trip row — `with extra as (select pickup_date, pickup_location_id from agg.agg_trip_zone_daily where pickup_date >= DATE '2024-01-01' and pickup_date < DATE '2024-04-01' except select trip_date, pickup_location_id from finance.mart_daily_zone_revenue where trip_date >= DATE '2024-01-01' and trip_date < DATE '2024-04-01') select count(*) as extra_zone_days, sum(a.trip_count) as extra_trips, round(sum(a.total_revenue),2) as extra_revenue, count(*) filter (where a.trip_count > 0) as with_trips from agg.agg_trip_zone_daily a join extra e on e.pickup_date = a.pickup_date and e.pickup_location_id = a.pickup_location_id`
- `agg_trip_zone_daily` grain is unique: 7,997 rows, 7,997 distinct `(pickup_date, pickup_location_id)` — `select count(*) as rows, count(distinct pickup_date || '|' || cast(pickup_location_id as varchar)) as distinct_zone_days from agg.agg_trip_zone_daily`
- `mart_daily_zone_revenue` grain is unique: 0 duplicate groups on `(trip_date, pickup_location_id)` — `select count(*) from (select trip_date, pickup_location_id from finance.mart_daily_zone_revenue group by 1,2 having count(*)>1)`
- `fct_trip` is clean on the measures this change reads: 97,184 rows, 97,184 distinct `trip_key`, no null in `fare_amount`, `tip_amount`, `total_surcharges`, `tolls_amount`, `total_amount` or `pickup_zone_key` — `select count(*) as rows, count(distinct trip_key) as distinct_keys, ... count(*) filter (where total_amount is null) as null_total from core.fct_trip`
- Zone attributes are stable across the seven versioned zones, and a naive `dim_zone` join on the natural key fans 7,997 aggregate rows out to 8,220; the as-of join the aggregate already carries is what keeps it at one row per zone-day — `select count(*) as naive_dim_zone_join_rows from (select a.pickup_date, a.pickup_location_id from agg.agg_trip_zone_daily a join core.dim_zone z on z.zone_natural_key = a.pickup_location_id) x`
- Every aggregate pickup location resolves in `dim_zone` (0 unresolved) and the aggregate carries 262 locations against the mart's 261 — `select count(*) as agg_location_ids_unresolved from (select distinct pickup_location_id from agg.agg_trip_zone_daily) a where not exists (select 1 from core.dim_zone z where z.zone_natural_key = a.pickup_location_id)`
- `reporting_region` is constant per zone in `dim_zone` (0 zones with more than one region) and is never null in the mart (0 of 7,961 rows) — `select count(*) as zones_with_region_variation from (select zone_natural_key from core.dim_zone group by 1 having count(distinct reporting_region) > 1) x`
- The reporting window's edges are whole days: 2024-01-01 and 2024-03-31 each carry all 24 pickup hours; eight interior days carry 23 of 24 — `select pickup_date, count(distinct pickup_hour) as hours, count(*) as trips from core.fct_trip group by 1 having count(distinct pickup_hour) < 24 order by 1`
- A re-aggregation of already-grouped billable sums reproduces the mart to the last bit at row level: 7,961 rows compared, 0 trip, fare or total differences, max absolute total difference 0.0 — `with level1 as (select f.pickup_date as d, f.pickup_zone_key as zone_key, count(*) filter (where f.is_billable) as trips, ... from core.fct_trip f where ... group by 1,2), level2 as (select l1.d, z.zone_natural_key as loc, sum(l1.trips) as trips, ... from level1 l1 join core.dim_zone z on z.zone_key = l1.zone_key where l1.trips > 0 group by 1,2) select count(*) as rows_compared, ... from finance.mart_daily_zone_revenue m join level2 l2 on l2.d = m.trip_date and l2.loc = m.pickup_location_id`
