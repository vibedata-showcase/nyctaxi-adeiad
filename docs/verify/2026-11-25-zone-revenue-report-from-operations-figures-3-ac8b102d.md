## Discovery

<!-- Written by designing: each discovery result, and any slice with its limits. Keep as found. -->

- **`agg_trip_zone_daily` is not an operations figure.** Its SQL reads only `ref('fct_trip')` and `ref('dim_zone')`; `grep -c "ops_raw\|fct_shift\|dim_driver" transformation/models/marts/agg/agg_trip_zone_daily.sql` returned `0`, exit 1 (no match). The same fact the finance report reads.

- **Q1 2024 totals, both relations.** `mart_daily_zone_revenue` returns 7,961 rows, 95,958 trips, 2,629,185.82 revenue, 261 zones. `agg_trip_zone_daily` returns 7,997 rows, 97,184 trips, 2,597,120.92 revenue. — `select 'mart_daily_zone_revenue' as rel, count(*) as rows, sum(trip_count) as trips, round(sum(total_revenue),2) as revenue, count(distinct pickup_location_id) as zones from finance.mart_daily_zone_revenue where trip_date >= date '2024-01-01' and trip_date < date '2024-04-01'`; and the same shape over `agg.agg_trip_zone_daily` with `pickup_date`.

- **JFK Airport, both relations.** Mart: 4,120 trips, 337,711.05 revenue. Agg: 4,261 trips, 329,766.06 revenue. — `select 'agg' as src, sum(trip_count) as trips, round(sum(total_revenue),2) as revenue from agg.agg_trip_zone_daily where pickup_date >= date '2024-01-01' and pickup_date < date '2024-04-01' and pickup_location_id = 132 union all select 'fin', sum(trip_count), round(sum(total_revenue),2) from finance.mart_daily_zone_revenue where trip_date >= date '2024-01-01' and trip_date < date '2024-04-01' and pickup_location_id = 132`

- **The revenue gap is the billable rule, fully accounted for.** Billable: 95,958 trips / 2,629,185.82. Non-billable: 1,226 trips / -32,064.90. 2,597,120.92 (−32,064.90) reconciles to 2,629,185.82. — `select is_billable, count(*) as trips, round(sum(total_amount),2) as revenue from core.fct_trip where pickup_datetime >= timestamp '2024-01-01' and pickup_datetime < timestamp '2024-04-01' group by 1 order by 1`; and the three-way `agg_rev / billable_rev / nonbillable_rev` query.

- **Ravi's figures reproduce from the fact independently of the mart.** Recomputing `count(*) filter (where is_billable)` and `sum(total_amount) filter (where is_billable)` from `core.fct_trip` gives 95,958 / 2,629,185.82 in total and 4,120 / 337,711.05 for JFK — the same as the mart, from a different expression.

- **The mart is a strict subset at zone-day grain.** 7,997 agg zone-days, 7,961 finance zone-days, 36 only in agg, 0 only in finance. The 36 carry 37 trips and -545.10: days whose only trips were non-billable. — `select ... from agg except select ... from fin` both directions.

- **On the 7,961 shared zone-days the two relations disagree on values.** 962 differ in `trip_count`, 954 differ in revenue, total missing revenue 31,519.80. — a join of `agg` to a billable aggregation of `fct_trip` on `(pickup_date, pickup_location_id)`.

- **`agg` carries all 7,997 zone-days at all-trip grain, exactly.** `a.trip_count = count(*)` on 7,997 of 7,997 keys; `a.total_revenue = sum(total_amount)` with 0.0 absolute difference over all keys. On billable-only the same join differs, which is the 31,519.80. — the `trips_equal_all / rev_diff_all / rev_diff_billable` query.

- **Dimension labels agree.** 0 differences in `zone_name` and in borough on all 7,961 shared keys. — a join on `(trip_date, pickup_location_id)`; a first attempt failed with `Binder Error: Column "pickup_date" does not exist on right side of join` and was re-run with aliased join keys.

- **Column gap.** `agg` has 14 columns, the mart 11. `agg` lacks `fare_revenue`, `tip_revenue`, `surcharge_revenue`, `toll_revenue` and `reporting_region`. — `information_schema.columns` for both relations.

- **No trip in the window has a null pickup zone**, so no row is dropped by either model's inner join to `dim_zone`. — `select count(*) ... from core.fct_trip where ... and pickup_zone_key is null` returned 0.

- **The window is fully covered at daily grain.** 91 calendar days in `dim_date`, 91 distinct days in each relation; first trip day 2024-01-01, last 2024-03-31. No cut-short period.

- **Change impact, `dbt ls`.** Downstream of `agg_trip_zone_daily`: `assert_semantic_content_holds`, `assert_semantic_levels_hold` (both generated by `ossie.py generate-tests`), and nothing else. No other model `ref()`s it.

- **The semantic layer binds the relation through exactly one source and one metric.** `LTS2_zone_day_agg` maps `pickup_date` and `trip_count` only; `trip_count` is its sole bound metric. The source's `note` already refuses `prev_day_trip_count`, `same_day_last_week_trip_count`, `trip_count_7d_avg` and `revenue_28d_rolling`; `total_miles`, `attributed_driver_count` and `revenue_rank_that_day` have no metric declared at all. Two `physical_joins` name the relation (`agg_trip_zone_daily_to_dim_date`, `agg_trip_zone_daily_to_Pickup_Zone`) and it appears in `physical_tables`.

- **Withdrawing the aggregate source loses no answer.** `trip_count` grouped by day and zone under the aggregate's content filter returns identical group sets from both routes: 7,997 groups from `agg_trip_zone_daily`, 7,997 from `fct_trip`, 0 rows only in one direction or the other. Confirmed through `semantic_query` at `target: domain`, `source: LTS2_zone_day_agg` versus `source: detail`, both filtered to `pickup_date >= DATE '2024-01-01' AND pickup_date < DATE '2024-04-01' AND pickup_zone_key IS NOT NULL`; and directly in SQL with `EXCEPT` both ways. `semantic_query` on the aggregate source is refused without the content filter (`compile_refused: the query filter does not imply its content filter`), which is why both calls carry it.

- **Nine design records list the relation as a dependency**, all in a `Depended on by:` line under `## Consumers`: `dim_date`, `dim_zone`, `fct_trip`, `stg_tlc__green_tripdata`, `stg_tlc__yellow_tripdata`, `stg_ops__trip_assignments`, `int_trips_conformed`, `int_trips_enriched`, `int_trip_quality_flags`. `grep -rln "agg_trip_zone_daily" docs/design/ | wc -l` returned 9.

- **The relation has no design record of its own** (`docs/design/models/agg/` holds only `agg_driver_daily.md` and `agg_od_flow_matrix.md`), no mention in `repo-map.json` or `test-map.json`, and no reference in `docs/adr/` or `ontology/`.
