## Discovery

Written by designing. Every upstream relation of `agg_borough_flow_monthly` was located and profiled against `domain`, which is where the repository's own dbt configuration and design records place them (`transformation/models/`, plus the `repo-map.json` layer declarations); no credential-free target check was needed because the relations exist only in the Domain database and the sandbox is a copy taken at activation.

- **`core.fct_trip` — `Ready`**, read on `domain`. 97,184 trips, 2024-01-01 to 2024-03-31, 95,958 billable; every month covers its whole calendar (31, 29 and 31 distinct pickup dates); 0 null `pickup_zone_key`, 0 null `dropoff_zone_key`; 0 null `total_amount` and 0 null `fare_amount` among billable trips; minimum billable `total_amount` 0.5. 106 billable trips have a null `payment_method_key`. — `select min(pickup_date) as min_d, max(pickup_date) as max_d, count(*) as trips, count(*) filter (where is_billable) as billable, count(*) filter (where pickup_zone_key is null) as null_pickup_key, count(*) filter (where dropoff_zone_key is null) as null_dropoff_key, count(*) filter (where pickup_zone_key is null and is_billable) as null_pickup_billable, count(*) filter (where dropoff_zone_key is null and is_billable) as null_dropoff_billable from core.fct_trip` and `select count(*) as billable_rows, count(*) filter (where total_amount is null) as null_total, count(*) filter (where fare_amount is null) as null_fare, count(distinct date_trunc('month', pickup_date)) as months, min(total_amount) as min_total from core.fct_trip where is_billable` and `select date_trunc('month', pickup_date) as m, count(distinct pickup_date) as n_days, min(pickup_date) as first_day, max(pickup_date) as last_day, count(*) as trips from core.fct_trip group by 1 order by 1`
- **`core.dim_zone` — `Ready`**, read on `domain`. 265 version rows, no null `borough_name`, 8 distinct boroughs: Manhattan 71 zones, Queens 69, Brooklyn 64, Bronx 45, Staten Island 20, EWR 1, Unknown 1, N/A 1; `is_unresolved_zone` is true exactly for Unknown and N/A; `is_nyc` is false for EWR, Unknown and N/A and true for the five city boroughs. — `select z.borough_name, count(*) as zones, count(*) filter (where z.is_unresolved_zone) as unresolved from core.dim_zone z group by 1 order by 2 desc` and `select borough_name, is_nyc, is_core_market, borough_code, reporting_region from core.dim_zone where is_current_version group by all order by 1`
- **`core.dim_payment_method` — `Ready`**, read on `domain`. 7 rows, 7 distinct keys, no null `counts_as_revenue`; `counts_as_revenue` is true for Flex Fare trip, Credit card and Cash, and false for No charge, Dispute, Unknown and Voided trip. — `select (select count(*) from core.dim_payment_method) as pm_rows, (select count(distinct payment_method_key) from core.dim_payment_method) as pm_distinct_keys, (select count(*) from core.dim_payment_method where counts_as_revenue is null) as pm_null_counts_as_revenue, (select count(*) from core.fct_trip where payment_method_key is null) as trip_null_pm_key, (select count(*) from core.fct_trip f left join core.dim_payment_method p on f.payment_method_key = p.payment_method_key where f.is_billable and p.payment_method_key is null) as billable_trips_without_pm` and `select payment_method_key, payment_method_name, settlement_class, counts_as_revenue, tip_is_captured from core.dim_payment_method order by 1`
- **Candidates under the floor**: 122 (month, origin borough, destination borough) combinations carry billable trips; 66 carry fewer than 25, of which 57 are cross-borough, holding 253 trips in total. At 25 trips and both ends a New York City borough, 39 rows remain: 94,624 trips, 2,494,501.46 recognised revenue, 3 months, 4 distinct origin boroughs and 4 distinct destination boroughs, smallest published pair 29 trips. — `with p as (select date_trunc('month', f.pickup_date) as m, o.borough_name as ob, dz.borough_name as db, count(*) as n from core.fct_trip f join core.dim_zone o on f.pickup_zone_key = o.zone_key join core.dim_zone dz on f.dropoff_zone_key = dz.zone_key where f.is_billable group by 1,2,3) select count(*) as existing_pairs, count(*) filter (where n < 25) as pairs_below_25, count(*) filter (where n < 25 and ob <> db) as cross_pairs_below_25, min(n) as min_n, sum(n) filter (where n<25) as trips_in_thin_pairs, sum(n) as all_trips from p` and `with pair as (select date_trunc('month', f.pickup_date) as m, o.borough_name as ob, o.is_nyc as o_nyc, d.borough_name as db, d.is_nyc as d_nyc, count(*) as trip_count, count(*) filter (where pm.counts_as_revenue) as recognised_trip_count, sum(f.total_amount) filter (where pm.counts_as_revenue) as recognised_revenue from core.fct_trip f join core.dim_zone o on f.pickup_zone_key = o.zone_key join core.dim_zone d on f.dropoff_zone_key = d.zone_key left join core.dim_payment_method pm on f.payment_method_key = pm.payment_method_key where f.is_billable group by 1,2,3,4,5), published as (select * from pair where o_nyc and d_nyc and trip_count >= 25) select count(*) as rows_published, sum(trip_count) as trips, sum(recognised_trip_count) as trips_with_revenue, round(sum(recognised_revenue),2) as revenue, count(distinct m) as months, count(distinct ob) as origins, count(distinct db) as destinations, min(trip_count) as min_pair_trips from published`
- **Revenue coverage inside the published set**: 93,261 of 94,624 published trips carry recognised revenue (98.56%); 103 published trips have a null payment-method key and contribute 0 recognised revenue. — `with pair as (select date_trunc('month', f.pickup_date) as m, o.borough_name as ob, d.borough_name as db, count(*) as trip_count, count(*) filter (where f.payment_method_key is null) as null_pm_trips, count(*) filter (where pm.counts_as_revenue) as revenue_trips, round(sum(f.total_amount) filter (where pm.counts_as_revenue),2) as revenue from core.fct_trip f join core.dim_zone o on f.pickup_zone_key = o.zone_key join core.dim_zone d on f.dropoff_zone_key = d.zone_key left join core.dim_payment_method pm on f.payment_method_key = pm.payment_method_key where f.is_billable and o.is_nyc and d.is_nyc group by 1,2,3) select sum(trip_count) as trips, sum(null_pm_trips) as null_pm_trips, sum(revenue_trips) as revenue_trips, round(sum(revenue),2) as revenue, round(100.0*sum(revenue_trips)/sum(trip_count),2) as pct_carrying_revenue from pair where trip_count >= 25`
- **The floor biases the share, which is why the denominator was asked**: computed over all the origin's New York City trips, Bronx January reads 58.88%; computed over its published pairs only, 49.43%. The user chose the published pairs (ADR 0019). — `with p as (select date_trunc('month', f.pickup_date) as m, o.borough_name as ob, dz.borough_name as db, dz.is_nyc as d_nyc, count(*) as n from core.fct_trip f join core.dim_zone o on f.pickup_zone_key = o.zone_key join core.dim_zone dz on f.dropoff_zone_key = dz.zone_key where f.is_billable group by 1,2,3,4) select m, ob, round(100.0 * sum(n) filter (where d_nyc and db <> ob) / nullif(sum(n) filter (where d_nyc), 0), 2) as share_all_trips, round(100.0 * sum(n) filter (where n >= 25 and d_nyc and db <> ob) / nullif(sum(n) filter (where n >= 25 and d_nyc), 0), 2) as share_published_only from p group by 1,2 order by 1,2`
