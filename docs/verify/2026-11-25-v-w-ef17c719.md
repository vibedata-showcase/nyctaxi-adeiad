### Population and share measurements

Borough-to-borough at billable-only, in-window (both zone roles joined on the surrogate key):

```sql
with t as (
  select date_trunc('month', f.pickup_date) as m, o.borough_name as ob, d.borough_name as db,
         o.is_unresolved_zone as o_unres, d.is_unresolved_zone as d_unres, o.is_nyc as o_nyc, d.is_nyc as d_nyc
  from core.fct_trip f
  join core.dim_zone o on f.pickup_zone_key = o.zone_key
  join core.dim_zone d on f.dropoff_zone_key = d.zone_key
  where f.is_billable and f.pickup_date >= date '2024-01-01' and f.pickup_date < date '2024-04-01'
)
select count(*) as billable_trips, count(*) filter (where o_unres or d_unres) as touches_unresolved,
       count(*) filter (where not o_nyc or not d_nyc) as touches_non_nyc,
       count(*) filter (where ob <> db) as naive_cross,
       count(*) filter (where ob <> db and not o_unres and not d_unres and o_nyc and d_nyc) as cross_resolved_nyc_only
from t
```

Result: `billable_trips 95958`, `touches_unresolved 1000`, `touches_non_nyc 1235`, `naive_cross 12214`, `cross_resolved_nyc_only 11249`.

```sql
with t as (
  select o.borough_name ob, d.borough_name db, o.is_unresolved_zone ou, d.is_unresolved_zone du, f.total_amount
  from core.fct_trip f
  join core.dim_zone o on f.pickup_zone_key = o.zone_key
  join core.dim_zone d on f.dropoff_zone_key = d.zone_key
  where f.is_billable and f.pickup_date >= date '2024-01-01' and f.pickup_date < date '2024-04-01'
)
select count(*) as trips, count(*) filter (where not ou and not du) as resolved_both,
       count(*) filter (where not ou and not du and ob <> db) as crossing_resolved_both,
       round(100.0 * count(*) filter (where not ou and not du and ob <> db) / count(*) filter (where not ou and not du), 2) as crossing_share_resolved,
       round(100.0 * count(*) filter (where not ou and not du and ob <> db) / count(*), 2) as crossing_share_of_all
from t
```

Result: `trips 95958`, `resolved_both 94958`, `crossing_resolved_both 11472`, `crossing_share_resolved 12.08`, `crossing_share_of_all 11.96`.

```sql
with f as (
  select date_trunc('month', f.pickup_date) as m, f.total_amount, o.borough_name ob, d.borough_name db
  from core.fct_trip f
  join core.dim_zone o on f.pickup_zone_key = o.zone_key
  join core.dim_zone d on f.dropoff_zone_key = d.zone_key
  where f.is_billable and f.pickup_date >= date '2024-01-01' and f.pickup_date < date '2024-04-01'
)
select round(sum(total_amount), 2) as fct_revenue, count(*) as fct_trips from f
```

Result: `fct_revenue 2629185.82`, `fct_trips 95958`. This is the population closure target for the table's `sum(trip_count)` and `sum(total_revenue)`.

```sql
with t as (
  select date_trunc('month', f.pickup_date) as m, o.borough_name ob, d.borough_name db, count(*) as trips
  from core.fct_trip f
  join core.dim_zone o on f.pickup_zone_key = o.zone_key
  join core.dim_zone d on f.dropoff_zone_key = d.zone_key
  where f.is_billable and f.pickup_date >= date '2024-01-01' and f.pickup_date < date '2024-04-01'
  group by 1, 2, 3
)
select count(*) as pairs_present, count(*) filter (where trips < 25) as pairs_under_25,
       (select count(distinct ob) from t) as distinct_origins, min(trips) as min_trips, max(trips) as max_trips
from t
```

Result: `pairs_present 122`, `pairs_under_25 66`, `distinct_origins 8`, `min_trips 1`, `max_trips 29849`. The full grid is 3 × 9 × 9 = 243 rows.

```sql
with p as (
  select date_trunc('month', f.pickup_date) as m, o.borough_name ob, d.borough_name db, count(*) trips
  from core.fct_trip f
  join core.dim_zone o on f.pickup_zone_key = o.zone_key
  join core.dim_zone d on f.dropoff_zone_key = d.zone_key
  where f.is_billable and f.pickup_date >= date '2024-01-01' and f.pickup_date < date '2024-04-01'
  group by 1, 2, 3
)
select m, count(*) pairs, count(*) filter (where trips < 25) under25,
       sum(trips) filter (where trips >= 25) trips_kept, sum(trips) all_trips
from p group by 1 order by 1
```

Result: 2024-01 — 40 pairs, 22 under 25, 29,886 kept of 29,985; 2024-02 — 40 pairs, 21 under 25, 29,962 of 30,017; 2024-03 — 42 pairs, 23 under 25, 35,857 of 35,956. A 25-trip floor would drop 253 trips.

```sql
with t as (
  select date_trunc('month', f.pickup_date) as m, o.borough_name ob, d.borough_name db,
         o.is_unresolved_zone o_u, d.is_unresolved_zone d_u, count(*) trips
  from core.fct_trip f
  join core.dim_zone o on f.pickup_zone_key = o.zone_key
  join core.dim_zone d on f.dropoff_zone_key = d.zone_key
  where f.is_billable and f.pickup_date >= date '2024-01-01' and f.pickup_date < date '2024-04-01'
  group by 1, 2, 3, 4, 5
)
select m, sum(trips) as all_trips,
       round(100.0 * sum(trips) filter (where ob <> db) / sum(trips), 2) as cross_any,
       round(100.0 * sum(trips) filter (where ob <> db and not o_u and not d_u) / sum(trips), 2) as cross_resolved_share_of_all,
       round(100.0 * sum(trips) filter (where ob <> db and not o_u and not d_u) / nullif(sum(trips) filter (where not o_u and not d_u), 0), 2) as cross_share_within_resolved
from t group by 1 order by 1
```

Result: 2024-01 — 29,985 trips, 12.79% crossing counting every trip, 11.69% as a share of all trips, 11.86% within resolved; 2024-02 — 30,017, 12.15%, 11.19%, 11.33%; 2024-03 — 35,956, 13.16%, 12.19%, 12.34%. The three definitions differ by about a percentage point, which is why the denominator was put to the user rather than chosen.

```sql
with trips as (
  select date_trunc('month', f.pickup_date) as m, o.borough_name ob, d.borough_name db, o.is_nyc o_nyc, d.is_nyc d_nyc,
         o.is_unresolved_zone o_u, d.is_unresolved_zone d_u
  from core.fct_trip f
  join core.dim_zone o on f.pickup_zone_key = o.zone_key
  join core.dim_zone d on f.dropoff_zone_key = d.zone_key
  where f.is_billable and f.pickup_date >= date '2024-01-01' and f.pickup_date < date '2024-04-01'
)
select m, ob as origin_borough, count(*) as trips,
       count(*) filter (where ob <> db) as cross_all,
       round(100.0 * count(*) filter (where ob <> db) / count(*), 1) as cross_share_pct_all,
       round(100.0 * count(*) filter (where ob <> db and not o_u and not d_u and o_nyc and d_nyc) / count(*), 1) as cross_share_pct_resolved_nyc
from trips where m = date '2024-01-01' group by 1, 2 order by trips desc
```

Result (January origins): Manhattan 26,593 trips, 6.0% / 5.3%; Queens 2,807, 71.5% / 68.1%; Brooklyn 349, 37.5% / 37.0%; Bronx 108, 59.3% / 58.3%; Unknown 98, 24.5% / 0.0%; N/A 13, 30.8% / 0.0%; Staten Island 11, 45.5% / 36.4%; EWR 6, 0.0% / 0.0%. An unresolved origin has no share under the chosen definition, which is why the model emits null there.
