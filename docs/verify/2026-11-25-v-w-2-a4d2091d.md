## Discovery

Measured by `designing` on the Domain warehouse to settle the design; every number below traces to the query beside it. Nothing here is a design decision — the decisions are in the design records.

- **The two relations differ in population, not in build.** `finance.mart_daily_zone_revenue` shows 95,958 trips / 2,629,185.82 revenue for Q1 2024; `agg.agg_trip_zone_daily` shows 97,184 / 2,597,120.92. `agg` applies no billable filter. — `select 'finance' as rel, sum(trip_count) t, round(sum(total_revenue),2) r from finance.mart_daily_zone_revenue where trip_date between date '2024-01-01' and date '2024-03-31' union all select 'agg', sum(trip_count), round(sum(total_revenue),2) from agg.agg_trip_zone_daily where pickup_date between date '2024-01-01' and date '2024-03-31'`
- **The gap is exactly the non-billable trips.** `fct_trip` holds 97,184 in-window trips, 95,958 billable; the 1,226 non-billable ones carry −32,064.90. 97,184 − 95,958 = 1,226 and 2,597,120.92 − 2,629,185.82 = −32,064.90, both exact. No trip has a null pickup zone. — `select count(*) as all_trips, count(*) filter (where is_billable) as billable_trips, count(*) filter (where not is_billable) as nonbillable_trips, round(sum(total_amount),2) as all_revenue, round(sum(total_amount) filter (where is_billable),2) as billable_revenue, round(sum(total_amount) filter (where not is_billable),2) as nonbillable_revenue, min(pickup_date) as first_day, max(pickup_date) as last_day, count(*) filter (where pickup_zone_key is null) as null_zone_trips from core.fct_trip where pickup_datetime >= timestamp '2024-01-01' and pickup_datetime < timestamp '2024-04-01'`
- **An aggregate cannot be split back apart.** 7,997 zone-days in the window; 962 mix billable with non-billable trips and 36 are entirely non-billable, so the billable subset is not recoverable from `agg`'s summed `total_revenue`. — `with b as (select pickup_date as d, pickup_location_id as z, count(*) filter (where is_billable) as bill_c, count(*) filter (where not is_billable) as nonbill_c, sum(total_amount) filter (where is_billable) as bill_rev, sum(total_amount) as all_rev from core.fct_trip where pickup_datetime >= timestamp '2024-01-01' and pickup_datetime < timestamp '2024-04-01' group by 1,2) select count(*) as zone_days, count(*) filter (where bill_c > 0 and nonbill_c > 0) as mixed_zone_days, count(*) filter (where bill_c = 0) as all_nonbillable_zone_days, round(sum(all_rev - bill_rev),2) as agg_minus_billable_rev from b`
- **The finance report is bit-exactly reproducible from the trip fact.** 7,961 rows, 0 unmatched pairs and 0 differing values on all six measures. — `with rebuild as (select f.pickup_date as d, z.zone_natural_key as z, ... sum(f.total_amount) as total_revenue from core.fct_trip f join core.dim_zone z on f.pickup_zone_key = z.zone_key where f.pickup_datetime >= timestamp '2024-01-01' and f.pickup_datetime < timestamp '2024-04-01' and f.is_billable group by 1,2,3,4,5), fin as (select trip_date as d, pickup_location_id as z, ... from finance.mart_daily_zone_revenue) select (select count(*) from rebuild) as rebuild_rows, (select count(*) from fin) as fin_rows, (select count(*) from rebuild full outer join fin using (d,z) where rebuild.z is null or fin.z is null) as unmatched, (select count(*) from rebuild join fin using (d,z) where rebuild.total_revenue is distinct from fin.total_revenue) as total_diff, ...`
- **A rebuild routed through the extended `agg` shape stays bit-exact.** The proposed seven-column shape, grouped by `pickup_date`, `pickup_location_id`, `zone_name`, `borough_name` and `reporting_region`, then filtered to `billable_trip_count > 0`, gives 7,961 rows, 0 unmatched, 0 measure differences, 0 attribute differences, 95,958 trips / 2,629,185.82 revenue and JFK 4,120 / 337,711.05 — and leaves 36 zero-billable zone-days in the upstream relation. Float summation order does not move any value. — `with new_agg as (select f.pickup_date, z.zone_natural_key as pickup_location_id, z.zone_name, z.borough_name, z.reporting_region, count(*) filter (where f.is_billable) as billable_trip_count, sum(f.total_amount) filter (where f.is_billable) as billable_revenue, ... from core.fct_trip f join core.dim_zone z on f.pickup_zone_key = z.zone_key where f.pickup_datetime >= timestamp '2024-01-01' and f.pickup_datetime < timestamp '2024-04-01' group by 1,2,3,4,5), report as (... where billable_trip_count > 0), fin as (...) select ...`
- **Extending `agg` leaves its own published values untouched.** Recomputing the relation with the added columns gives the same 7,997 rows, 0 unmatched pairs and 0 differences in `trip_count`, `total_revenue`, `total_miles`, `attributed_driver_count`, `zone_name`, `borough_name` and `pickup_date_key`. — `with new_agg as (... old_agg as (select pickup_date as d, pickup_location_id as z, trip_count, total_revenue, total_miles, attributed_driver_count, zone_name, borough_name from agg.agg_trip_zone_daily) select (select count(*) from new_agg) as new_rows, (select count(*) from old_agg) as old_rows, (select count(*) from new_agg n full outer join old_agg o on n.pickup_date=o.d and n.pickup_location_id=o.z where n.pickup_date is null or o.d is null) as unmatched, (select count(*) from new_agg n join old_agg o on ... where n.trip_count is distinct from o.trip_count or ... ) as existing_value_diff`
- **`reporting_region` is the only report attribute `agg` lacks, and it is constant per zone-day.** `agg` carries `zone_name`, `borough_name` and `pickup_location_id` but not `reporting_region`; `dim_zone.reporting_region` resolves identically however it is reached, so carrying it in `agg` groups without splitting any grain (4 non-null regions over the window, 0 nulls). — `with cand as (select a.pickup_date as d, a.pickup_location_id as z, z.reporting_region from agg.agg_trip_zone_daily a join core.dim_zone z on a.pickup_location_id = z.zone_natural_key and z.is_current_version where ...), fin as (select trip_date as d, pickup_location_id as z, reporting_region from finance.mart_daily_zone_revenue) select ...`
- **A bare natural-key join to `dim_zone` fans out; the version must be resolved.** `dim_zone` holds 272 rows and 7 natural keys in more than one version, so joining `agg` on `zone_natural_key` alone turns 223 zone-days into multiple rows. An as-of join on `valid_from_date`/`valid_to_date` gives 7,961 rows with 0 region differences, and no `(natural key, valid_from_date)` pair repeats. — `with report_b as (select a.pickup_date as d, a.pickup_location_id as z, dz.reporting_region from new_agg a join core.dim_zone dz on a.pickup_location_id = dz.zone_natural_key and a.pickup_date >= dz.valid_from_date and (dz.valid_to_date is null or a.pickup_date < dz.valid_to_date) where a.billable_trip_count > 0) select ...`
- **No measure needs a coverage count.** All 95,958 billable in-window trips carry a non-null `fare_amount`, `tip_amount`, `total_surcharges`, `tolls_amount` and `total_amount`. — `select count(*) as billable_rows_q1, count(*) filter (where fare_amount is null) as fare_null, count(*) filter (where tip_amount is null) as tip_null, count(*) filter (where total_surcharges is null) as surch_null, count(*) filter (where tolls_amount is null) as toll_null, count(*) filter (where total_amount is null) as total_null from core.fct_trip where is_billable and pickup_datetime >= timestamp '2024-01-01' and pickup_datetime < timestamp '2024-04-01'`
- **Neither window edge is cut short.** 2024-01-01 carries 888 trips across all 24 hours (first 00:05:25, last 23:59:25) and 2024-03-31 carries 975 across all 24 (first 00:00:22, last 23:56:17), so no incomplete-period mark is owed. — `select pickup_date, count(*) as trips, min(pickup_datetime) as first_trip, max(pickup_datetime) as last_trip, count(distinct extract(hour from pickup_datetime)) as hours from core.fct_trip where pickup_datetime >= timestamp '2024-01-01' and pickup_datetime < timestamp '2024-04-01' and (pickup_date = date '2024-01-01' or pickup_date = date '2024-03-31') group by 1 order by 1`
- **`F-01` is real.** `mart_daily_zone_revenue.trip_count`'s properties description reads "Trips, billable or not", but over all 7,961 rows it never differs from the billable count. — `select (select count(*) from f join b using (d,z) where f.trip_count <> b.billable_cnt) as fin_vs_billable_cnt_mismatch` against `fct_trip`'s `count(*) filter (where is_billable)`.
- **Input adequacy: `Ready`.** Read on `target: "domain"`, established by the Requirement naming the Domain warehouse and by `lakehouse_schema` finding both relations there. Every upstream relation is populated, keys are unique at both grains (0 duplicate `(date, zone)` pairs in either relation), no scoping date landed as text, and no measure the design reads is null.
